# 换机接续：系统主题与 Icon 直接 CSS 属性

## 代码位置

- 仓库：https://github.com/kenconnet666/zerodep-svelte-ui
- 当前研发分支：codex/dependencies-and-quality。换机后继续此分支，不从旧 main 重做。
- 系统类型和预设：packages/ui/src/lib/provider/theme/。
- CSS 主题作者：packages/ui/src/lib/provider/css.ts，显式属性类与 getter，不使用 Proxy。
- Icon：packages/ui/src/lib/display/gene/Icon.svelte；外观 props 直接使用 UiCss 对应 raw() 的输入类型。
- src/lib/index.ts 自动导出，仍通过包名导入 Icon；内部 context 不公开。
- 详细字段、默认值和 CSS 输入规则见 [主题设计](theme-tokens.md)，文档站 /provider 和 /icon 有说明与交互示例。

## 已确定的约定

- 系统主题通过 JS 对象、Svelte context 和 getter 工作；iem 已取消，不实现 CSS 变量主题。
- 根 Provider 默认 lightTheme，嵌套继承。组件必须在 Provider 后代中使用。
- useTheme/useLocale/useLang 分开；没有 UiConfig/useConfig。
- 系统 token 键统一带下划线，如 _primary、_md；主题声明保持同名，例如 s.color._primary、s.color.raw('_primary')，Icon 的 color="_primary"、size="_md" 同理。
- 系统 theme 采用完整对象替换，嵌套主题由各自的 UiCss 消费。通用 token 各组件直接复用；组件专用值就近写在组件内部，通过同一套 CSS 工具生成声明，class 是外部样式定制入口。不建立组件 token 注册、注入、覆盖或合并基础设施。
- Icon 的 size/color/strokeWidth/verticalAlign 默认值在 $props() 中声明为 _md/inherit/2/-0.125em；支持系统 token 与对应原生 CSS 输入。
- 系统字号 _lg 是 20px、_xl 是 24px，Icon 直接使用同名档位。描边与其他外观属性一样直接使用 raw()，没有 bx 或关键字分支。
- 本次没有改动 zerodep-css；仍消费 catalog 固定的 0.1.3，不依赖本机 link、私有补丁或绝对路径。

## lucide 名称入口

Icon 的 lucide 支持 i => i.search 编译时成员选择和字符串字面量，与 icon 二选一。LucideIcons 是脚本生成的显式成员接口，多词名称使用 i.circlePlus；插件只解析成员，不执行回调或创建全量对象。消费者使用 zerodep-svelte-ui/vite，放在 Svelte/SvelteKit 前，CSS 绑定插件仍需启用。名称类型通过 pnpm lucide:generate 从官方名称列表生成本地显式字面量联合，pnpm lucide:check 检查同步；不在浏览器加载全量图标。动态选择仍用 icon={数据}。实现和支持边界见 [lucide 编译入口](lucide-prop.md)。

## 新机器准备

使用 Node 24 和 package.json 指定的 pnpm 10.34.5。在仓库目录执行：

```powershell
git fetch origin
git switch codex/dependencies-and-quality
git pull --ff-only
pnpm install --frozen-lockfile
pnpm sync
pnpm lsp:setup
pnpm check
pnpm dev
```

信任并重新打开项目后核对 LSP MCP 是否连接。.codex/config.toml 为本机生成文件，不复制旧机器路径；dist/build/.svelte-kit 也不必迁移。若用户级 .npmrc 使用 NPM_TOKEN，占位变量需要由新机器的进程环境提供，令牌不放入仓库。

## 建议下一步

以 Button 和 Input 为下一阶段：复用系统 controlHeight 等通用 token，专用 padding、图标与状态样式直接在组件内部定义，通过 class 支持外部定制。组件 token 覆盖体系不属于后续计划。复杂组件需要子部件协作时，只按实际交互行为设计 context。
