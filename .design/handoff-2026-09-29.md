# 换机接续：系统主题与 Icon 组件 token

## 代码位置

- 仓库：https://github.com/kenconnet666/zerodep-svelte-ui
- 当前研发分支：codex/dependencies-and-quality。换机后继续此分支，不从旧 main 重做。
- 系统类型和预设：packages/ui/src/lib/provider/theme/。
- CSS 主题作者：packages/ui/src/lib/provider/css.ts，显式属性类与 getter，不使用 Proxy。
- 组件覆盖类型：packages/ui/src/lib/provider/component-themes.ts。
- Icon：packages/ui/src/lib/display/gene/Icon.svelte；同目录 icon-theme.ts 定义 IconTokens 和默认值派生。
- src/lib/index.ts 自动导出，仍通过包名导入 Icon；内部 context 不公开。
- 详细字段、默认值和分层规则见 [主题设计](theme-tokens.md)，文档站 /provider 和 /icon 有说明与交互示例。

## 已确定的约定

- 系统主题通过 JS 对象、Svelte context 和 getter 工作；iem 已取消，不实现 CSS 变量主题。
- 根 Provider 默认 lightTheme，嵌套继承。组件必须在 Provider 后代中使用。
- useTheme/useLocale/useLang 分开；没有 UiConfig/useConfig。
- 系统与组件 token 键统一带下划线，如 _primary、_md、_sizeMd；主题声明保持同名，例如 s.color._primary、s.color.raw('_primary')，Icon 的 color="_primary"、size="_md" 同理。
- 系统 theme 采用完整对象替换。组件覆盖则逐字段合并：当前系统主题派生默认值 → 外层 Provider → 内层 Provider → 实例 tokens。undefined 不覆盖，0 是有效覆盖。
- Provider 只传递组件的显式覆盖项，组件在本级主题下计算默认值，防止父级亮色默认值覆盖子级暗色主题。
- 当前组件映射仅有 Icon。Icon 是叶子组件，不提供无用途的 useIconTheme，不创建独立 Css 实例。
- 系统字号 _lg 是 20px、_xl 是 24px；Icon _lg 使用 _xl，因此图标默认仍为 14/16/24px（根字号 16px）。显式 strokeWidth prop 高于组件 token。
- 本次没有改动 zerodep-css；仍消费 catalog 固定的 0.1.3，不依赖本机 link、私有补丁或绝对路径。

## 新机器准备

使用 Node 24 和 package.json 指定的 pnpm 10.34.5。在仓库目录执行：

```powershell
git fetch origin
git switch codex/dependencies-and-quality
git pull --ff-only
pnpm install --frozen-lockfile
pnpm sync
pnpm lsp:setup
pnpm check
pnpm dev
```

信任并重新打开项目后核对 LSP MCP 是否连接。.codex/config.toml 为本机生成文件，不复制旧机器路径；dist/build/.svelte-kit 也不必迁移。若用户级 .npmrc 使用 NPM_TOKEN，占位变量需要由新机器的进程环境提供，令牌不放入仓库。

## 建议下一步

以 Button 和 Input 为下一阶段：先确定共享 controlHeight 档位，再各自定义 padding、图标与状态 token。继续采用扁平组件 token 和简单覆盖，不提前引入通用 variants、递归 peers 或 DeepPartial 合并框架。复杂组件真正需要子部件时，再增加该组件专属 context。
